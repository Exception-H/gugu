# 验收清单

本清单只汇总仓库里**已有脚本**的口径，方便提交 PR 前自查。命令均以仓库根目录为工作目录。

## 1. 工具链版本

| 项目 | 要求 | 来源 |
| --- | --- | --- |
| Node | **24.14.0**（精确等值，`>=` 不满足） | `.node-version` |
| pnpm | 10.28.2 | `package.json#packageManager` |
| Electron 原生模块 | 每次 `pnpm install` 后需 `pnpm rebuild:native` | `scripts/build/verify-dev-native.mjs` |

`scripts/build/node-version-preflight.mts` 读取 `.node-version` 后要求**当前版本与之完全相等**，
24.21.0 之类更高版本同样会被拒绝，且 preflight 不会自动切换工具链。

本地可以把钉死的 Node 前置进 PATH（不动全局 node）：

```bash
source ~/tools/mac-workspace/gugu-env.sh      # 当前 shell 生效
source ~/tools/mac-workspace/gugu-env.sh --cd # 生效并 cd 到项目目录
```

如果这个脚本不存在，直接用 `~/.local/node-v24.14.0/bin` 前置 PATH 即可。

## 2. 安装依赖

```bash
pnpm install --frozen-lockfile
pnpm rebuild:native        # 为 Electron 编译原生模块，否则 dev 启动时 pty.node 缺失
```

## 3. 类型检查

```bash
pnpm typecheck             # = pnpm preflight:node && tsgo --noEmit
```

`preflight:node` 先校验 Node 版本，所以 Node 版本不对时第一步就会失败，报错不是类型问题。

## 4. 测试

```bash
pnpm test:unit             # 单测：gugu / tooling / session-packages / session-main / session-chat-ui
pnpm test                  # gugu-integration 集成测试
pnpm test:browser          # session-browser / session-chat-ui-browser（需先 pnpm exec playwright install chromium）
pnpm session:test:db       # 会话库相关用例
```

### ⚠️ 不要一次性跑全量 vitest

直接跑 `pnpm exec vitest run`（或任何不按 `--project` / 文件收窄的全量跑法）会在跑到
**第 53 个用例时被 SIGKILL**，既得不到可用结果，也不会打印失败用例。

请按下面任一方式收窄后再跑：

```bash
pnpm test:unit                                                     # 按项目分组
pnpm exec vitest run --project session-main <某个测试文件或目录>    # 单个项目 + 单文件
```

需要全量覆盖时逐个项目、逐个目录跑，把结果拼起来，不要指望一次全量跑完。

## 5. 提交前自查

```bash
pnpm typecheck
pnpm lint                  # eslint + 各项仓库检查脚本（console 用法、错误出口、用户文案泄漏等）
pnpm test:unit             # 分项目跑，见上面的警告
pnpm build:renderer        # 渲染层构建
git status --porcelain     # 应为空
```

## 6. 分支与 PR

- 从最新 `origin/dev` 切分支，PR 目标分支是 `dev`（`main` 是发布通道，由维护者晋级）。
- 不直接向 `dev` / `perf/ui-experience` 推送，不合并自己的 PR。
- PR 描述里写清改了什么、跑了哪些命令、输出是什么。
